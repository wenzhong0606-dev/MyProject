# 软件产品工程生命周期（12 阶段）

| 阶段 | 主要活动 | 最低交付物 |
|---|---|---|
| 01 产品定位 | 目标、边界、指标 | 产品定位与范围 |
| 02 需求分析 | 角色、场景、优先级 | 需求清单与验收条件 |
| 03 业务流程 | AS-IS/TO-BE、异常路径 | BPMN、业务规则 |
| 04 领域建模 | 对象、关系、状态 | 领域模型、术语表 |
| 05 功能架构 | 功能、菜单、权限 | 功能树、权限矩阵 |
| 06 交互原型 | 任务流、页面状态 | 原型与交互说明 |
| 07 数据设计 | 逻辑模型、约束、审计 | 数据字典、ER 图 |
| 08 技术设计 | API、架构、安全、并发 | 技术设计与接口契约 |
| 09 开发实现 | 任务拆分、编码、单测 | 代码与测试 |
| 10 测试验收 | 功能、权限、异常、性能 | 测试证据、UAT |
| 11 部署发布 | 迁移、回滚、监控 | 发布与回滚计划 |
| 12 运营迭代 | 指标、反馈、改进 | 迭代计划 |

业务模型和流程需要反复校验；页面与数据设计可并行推进。已批准成果可复用，按任务裁剪，变更需做影响分析。

## 12 阶段产出目录

阶段成果存储于 [docs/deliverables](../deliverables/README.md)，文件结构以 [manifest.json](../deliverables/manifest.json) 为准。阶段成果与治理规范严格分离。

## 文件的职责与范围

各阶段的成果文件职责、需要输出的内容和禁止混写的内容参见 [交付物职责清单](./deliverables-catalog-交付物职责清单.md)。
