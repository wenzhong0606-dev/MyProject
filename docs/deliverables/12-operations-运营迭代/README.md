# 12 运营迭代 — operations Deliverables

- **阶段职责**：基于真实运行数据持续改进
- **输入**：已批准的立项依据或上游已批准成果；引用时写明来源和版本
- **当前阶段状态**：NOT_STARTED（仅有模板）
- **适用门禁**：持续评审
- **输出**：本目录独立成果文件，满足对应评审标准后才能申请门禁

## 独立成果清单

| 文件 | 核心作用 | 使用边界 | 状态 |
|---|---|---|---|
| [operations-metrics-运营指标.md](./operations-metrics-运营指标.md) | 跟踪上线后的真实业务指标、技术指标、口径与趋势 | 不直接复用立项目标当实际值 | DRAFT |
| [feedback-用户反馈.md](./feedback-用户反馈.md) | 记录用户反馈来源、影响角色、严重性及事实证据 | 不将反馈直接当作批准的需求 | DRAFT |
| [improvement-backlog-迭代需求.md](./improvement-backlog-迭代需求.md) | 将运营改进转换为可优先级排序的迭代项及预期收益 | 不直接等同开发任务已排期 | DRAFT |
| [retrospective-复盘报告.md](./retrospective-复盘报告.md) | 分析阶段目标完成度、根因、改进责任人与跟进验证 | 不隐瞒失败或未完成事项 | DRAFT |

## 阶段完成要求

必须完成内容评审、上下游一致性检查、追踪更新及人工门禁审批；模板存在不等于完成。详细职责见 [全量文件职责目录](../../governance/deliverables-catalog-交付物职责清单.md)。
