# 08 技术设计 — architecture Deliverables

- **阶段职责**：落实系统工程实现方案
- **输入**：已批准的立项依据或上游已批准成果；引用时写明来源和版本
- **当前阶段状态**：NOT_STARTED（仅有模板）
- **适用门禁**：G4
- **输出**：本目录独立成果文件，满足对应评审标准后才能申请门禁

## 独立成果清单

| 文件 | 核心作用 | 使用边界 | 状态 |
|---|---|---|---|
| [architecture-架构方案.md](./architecture-架构方案.md) | 定义模块分层、部署单元、依赖关系及技术决策依据 | 不重新定义业务对象和规则 | DRAFT |
| [api-contracts-API契约.md](./api-contracts-API契约.md) | 定义 API 端点、输入输出、鉴权、错误码与版本约定 | 不替代业务功能规格 | DRAFT |
| [security-nfr-安全非功能要求.md](./security-nfr-安全非功能要求.md) | 定义安全、性能、可用性、容量、并发及恢复目标 | 不在未经评估时声称符合标准 | DRAFT |
| [integration-集成方案.md](./integration-集成方案.md) | 规定上下游系统、集成责任、协议、失败重试及幂等性 | 不复制外部系统全部接口源码 | DRAFT |

## 阶段完成要求

必须完成内容评审、上下游一致性检查、追踪更新及人工门禁审批；模板存在不等于完成。详细职责见 [全量文件职责目录](../../governance/deliverables-catalog-交付物职责清单.md)。
