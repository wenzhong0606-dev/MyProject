# 02 需求分析 — requirements Deliverables

- **阶段职责**：明确建设需求与验收边界
- **输入**：已批准的立项依据或上游已批准成果；引用时写明来源和版本
- **当前阶段状态**：NOT_STARTED（仅有模板）
- **适用门禁**：G1
- **输出**：本目录独立成果文件，满足对应评审标准后才能申请门禁

## 独立成果清单

| 文件 | 核心作用 | 使用边界 | 状态 |
|---|---|---|---|
| [stakeholders-角色与干系人.md](./stakeholders-角色与干系人.md) | 识别业务参与者、职责、利益诉求及沟通边界 | 不等同于最终系统权限配置 | DRAFT |
| [scenarios-业务场景.md](./scenarios-业务场景.md) | 列出用户在何种条件下完成何种工作及预期结果 | 不代替细化的流程与状态图 | DRAFT |
| [requirements-需求规格.md](./requirements-需求规格.md) | 为每项需求定义唯一编号、来源、优先级、约束 | 不描述数据库表结构或直接实现代码 | DRAFT |
| [acceptance-criteria-验收条件.md](./acceptance-criteria-验收条件.md) | 将需求转化为可客观判定的验收条件和反例 | 不等同于测试运行报告 | DRAFT |

## 阶段完成要求

必须完成内容评审、上下游一致性检查、追踪更新及人工门禁审批；模板存在不等于完成。详细职责见 [全量文件职责目录](../../governance/deliverables-catalog-交付物职责清单.md)。
