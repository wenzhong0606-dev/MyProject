# 10 测试验收 — qa Deliverables

- **阶段职责**：证明需求符合性并完成业务验收
- **输入**：已批准的立项依据或上游已批准成果；引用时写明来源和版本
- **当前阶段状态**：NOT_STARTED（仅有模板）
- **适用门禁**：G5/G6
- **输出**：本目录独立成果文件，满足对应评审标准后才能申请门禁

## 独立成果清单

| 文件 | 核心作用 | 使用边界 | 状态 |
|---|---|---|---|
| [test-plan-测试方案.md](./test-plan-测试方案.md) | 定义测试层次、范围、环境、覆盖策略和准入退出标准 | 不代替具体测试用例 | DRAFT |
| [test-cases-测试用例.md](./test-cases-测试用例.md) | 以需求和功能 ID 列出正常、边界、权限与异常场景 | 不将未执行的用例写成通过 | DRAFT |
| [defects-缺陷与回归.md](./defects-缺陷与回归.md) | 维护缺陷编号、严重程度、复现步骤、责任人与回归证据 | 不在无证据时关闭问题 | DRAFT |
| [uat-用户验收.md](./uat-用户验收.md) | 登记业务代表的试用结果、遗留问题、签字与批准日期 | AI 不得代替用户批准 | DRAFT |

## 阶段完成要求

必须完成内容评审、上下游一致性检查、追踪更新及人工门禁审批；模板存在不等于完成。详细职责见 [全量文件职责目录](../../governance/deliverables-catalog-交付物职责清单.md)。
